EAiOS Module Assessment

Proposed modules: Document-to-Podcast generator (Notebook LM-style) and Social Media Scheduler.

Prepared: 12 Sep 2026

Bottom line up front:
  • Podcast module: Very doable. Google has an official Podcast API, and a solid open-source Python package (Podcastfy) already does exactly this. I recommend a spike that compares Google API quality/cost vs. self-hosted Podcastfy.
  • Social scheduler: Doable for LinkedIn, Facebook, X, and YouTube. Snapchat is the problem — Snap has no public API for organic posts (Stories, Snaps, Spotlight). You will need a unified API provider or build direct integrations. Direct integrations are high-complexity; a unified API is the pragmatic path.

1. Document-to-Podcast Module

Upload a DOCX or PDF; get back a conversational two-host MP3 podcast.

Option A: Google Gemini Notebook Enterprise Podcast API

  • What it is: Official Google API that replicates Notebook LM's "Audio Overview" output.
  • Endpoint: discoveryengine.googleapis.com/v1/projects/PROJECT_ID/locations/global/podcasts
  • Input: Text, images, audio, video; total context <100k tokens.
  • Output: MP3; SHORT = ~4-5 min, STANDARD = ~10 min.
  • Requirements: GCP project, Discovery Engine API enabled, roles/discoveryengine.podcastApiUser IAM role.
  • Pros: Produces the exact Notebook LM quality Don wants; managed, no ML ops.
  • Cons: Pricing is not published separately; likely billed via Gemini Enterprise/Discovery Engine. Long-running async job (poll operation, then download).

Option B: Podcastfy (open source)

  • What it is: 6.5k-star Apache-2.0 Python package purpose-built as an open-source alternative to Notebook LM's podcast feature.
  • Inputs: PDFs, websites, images, YouTube videos, plain text, or just a topic.
  • Models: Plugs into 100+ LLMs (OpenAI, Anthropic, Google, OpenRouter, local via Ollama).
  • Voices: OpenAI, Google, ElevenLabs, Microsoft Edge TTS.
  • Pros: No lock-in, predictable per-API-call cost, can use existing OpenRouter key, runs in EAiOS sidecar.
  • Cons: Quality may trail Google's own model; requires prompt tuning to match the natural back-and-forth of Notebook LM.

Podcast Module: Risk / Complexity / Estimate

DimensionRatingNotes
Technical complexityMediumFile extraction (PDF/DOCX → text), async job queue, audio storage, player UI.
External dependency riskMediumGoogle API pricing/availability is unclear; Podcastfy depends on LLM + TTS providers.

Recommendation: Run a 1-day spike generating the same document through both Google Podcast API and Podcastfy. Compare audio quality, latency, and cost. Then pick one and build the upload → queue → listen UI in EAiOS.

2. Social Media Scheduling Module

Compose once, schedule posts to LinkedIn, Facebook, X, YouTube — and Snapchat.

Option A: Build direct platform integrations

  • Implement 4–5 different OAuth flows, token refreshers, rate-limit handlers, and content validators.
  • LinkedIn and Meta require app review/MDP partnership; review times 1–4 weeks.
  • X pay-per-use makes cost unpredictable.
  • Snapchat organic posting is effectively impossible.

Snapchat reality check: Even unified APIs cannot post organic Snapchat Stories/Snaps because Snap does not expose that capability. If Snapchat is non-negotiable, the only realistic path is a mobile-automation/browser workflow, which is fragile and approval-gated.

Recommendation: Start with a unified API (my pick: Zernio for per-account pricing, or Ayrshare if you want the most mature option). Build the composer + schedule queue + status dashboard. Treat Snapchat as a manual exception until Snap opens organic publishing.

Final Recommendation

  1. Podcast module: Green-light the spike. It is the lower-risk, higher-delight feature and fits EAiOS's document-heavy knowledge workflow.
  2. Social scheduler: Green-light only if Don accepts that Snapchat cannot be automated cleanly. If Snapchat is mandatory, scope the first version to LI/FB/X/YT and flag Snapchat as a separate, high-risk automation spike.
  3. Order of attack: Podcast first (1–1.5 weeks), then social scheduler (1.5–2 weeks with unified API).
