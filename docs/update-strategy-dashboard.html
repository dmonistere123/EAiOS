Deliverables

1. Update Script

scripts/eaios-update.sh — deliberate, one-command update for shipped boxes.
  • Records old/new git SHA + version in eaios_update_log SQLite table
  • Detects no-change (same commit) and skips build/restart
  • Runs migrations after pull
  • Re-renders systemd units, restarts services, runs verification
  • Stops on first error and logs failure

2. Migration Runner

scripts/run-migrations.mjs + migrations/ directory.
  • Numbered SQL migrations applied once, tracked in _eaios_migrations table
  • SHA-256 checksum verification prevents tampering with already-applied migrations
  • Initial migration sets up version tracking schema
  • Idempotent: safe to run repeatedly

3. Version Tracking

Build-time version.json generated by scripts/generate-version.mjs.
  • Captures semver (package.json), git SHA, branch, nearest tag, release channel (stable/rc/dev)
  • Generated before every npm run build and npm run dev
  • Served via GET /api/version in both dev (vite) and prod (node:http)
  • Includes update history tail from eaios_update_log

4. UI Visibility

Settings page now includes a "Version & Updates" panel.
  • Shows current version, git SHA, branch, build timestamp
  • Shows last 5 update entries (success/failure, SHA transition, error messages)
  • Explains the deliberate-update philosophy (no OTA)
  • Works in both live and mock adapter modes

5. Updated Docs

  • docs/design-update-path-2026-09-14.md — refined with implementation status
  • docs/INSTALL.md — new "Updating a shipped box" section
  • migrations/README.md — migration authoring guide

Open Questions (from the design doc)

  1. Git access: Do shipped boxes have outbound git access? The update script assumes yes. If not, a tarball/USB channel can be added.
  2. Approval gate: Should the update require an EAiOS approval envelope? Currently it's a CLI command — the CEO or support team runs it deliberately. Adding an approval envelope is straightforward but was deferred.
  3. Rollback: The script records old/new SHAs but does not git revert. Manual rollback (re-run install.sh) is documented.
  4. Cadence: Every commit, tagged releases, or on-demand? The script works on any branch — pick your cadence.
